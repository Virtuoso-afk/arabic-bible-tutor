# Final learner experience proposal

**Status:** reviewable PD-004 synthesis. The proof demonstrates deterministic local state; it does not provide accounts, persistence, AI, or real evaluation.

## Experience model

Learning remains the product spine: orient, learn, practice, receive feedback, demonstrate evidence, and choose the next step. The AI tutor is available inside a lesson and receives only the current objective, approved source set, attempt context, and safety configuration. It does not replace curriculum, exercises, or teacher review.

The learner always sees the active path. Switching paths changes courses, progress dimensions, assessment language, and tutor mode. It never merges progress.

## Landing

The landing page establishes a premium but energetic identity through a spacious A-derived composition and a B-derived course journey on a navy brand surface. The first viewport contains:

- provisional `نَسَق` identity and honest prototype label;
- the shared value proposition, “meaningful progress and durable learning”;
- a route diagram showing observe, practice, apply, and demonstrate;
- two honest actions: inspect paths or open the local lesson proof;
- explicit notice that there are no accounts or real AI.

Below the hero, equal path cards explain separate outcomes. The language path uses teal and language-skill terms; the study path uses plum and source-literacy terms. A three-step learning loop and future-course region explain the shared educational framework without making the brand Bible-specific.

### Landing responsive behavior

- **Mobile:** one-column hero, full-width actions, journey below copy, stacked path cards, and no hidden core information.
- **Tablet:** one-column hero preserves a large readable journey, followed by stacked cards.
- **Desktop:** balanced two-column hero and paired path cards use available width without widening body text.

## Learner dashboard

The dashboard leads with the current lesson and estimated effort. It then shows a simplified course journey and separate path-specific progress cards. The hierarchy is:

1. personalized welcome and current context;
2. continue-learning action;
3. course journey with current station and next competency;
4. Path A language skills and Path B study competencies, never combined into one mastery score;
5. optional review, earned achievement, and weekly evidence.

The weekly goal is explicitly flexible. The achievement “قارئ متأنٍ” describes demonstrated behavior and is private. Time spent is informational and does not affect mastery. There is no streak, leaderboard, rank, currency, or loss state.

### Dashboard responsive behavior

- **Mobile:** sidebar becomes a four-destination bottom navigation; all content is one column; route labels remain visible; path progress cards stack; supporting cards follow the learning content.
- **Tablet:** the sidebar collapses to an icon rail; dashboard side cards form a three-card row after the primary content.
- **Desktop:** a 238 px RTL rail remains persistent; the main dashboard and supporting column use a stable two-column grid.

## Interactive lesson

The proof demonstrates Path B because source layers are easiest to inspect there. The same lesson frame supports Path A with language exercises and its own progress dimensions.

The lesson header shows progress and exit/resume behavior. The desktop outline identifies the current step; mobile uses a compact bottom utility bar. The learning region presents:

1. **Source reference:** `لوقا ١٠: ٢٥–٣٧`, with no passage text and an explicit licensing notice.
2. **Activity objective:** distinguish a source observation from interpretation or curriculum guidance.
3. **Educator guidance:** a reviewed rule that defines the distinction.
4. **Accessible answer choices:** native buttons with visible selection, correct state, icons, and explanatory descriptions.
5. **Progressive hint:** first points to the reasoning method; the next offers a more direct clue.
6. **Feedback:** explains why the answer works and records a simulated, path-specific evidence statement.
7. **Contextual tutor:** shows scope, generated-content label, citation, prompt starters, and a clear simulation disclosure.

The exercise does not grade belief, doctrine, or personal devotion. It evaluates source-literacy behavior. The reference is not reproduced, and no permission is claimed.

### Lesson interactions in the proof

- Selecting an answer changes a visible and programmatic button state.
- Checking a correct answer reveals explanatory feedback.
- Checking another answer offers remediation and opens the hint.
- Hint controls reveal a second, clearer hint.
- Tutor prompt buttons return deterministic, contextual responses.
- A typed question returns a simulation notice rather than pretending to contact an AI service.
- Landing and dashboard actions navigate among the standalone screens.

### Lesson responsive behavior

- **Mobile:** outline is replaced by the progress header and utility bar; source, guidance, activity, hint, feedback, and tutor stack in reading order; no fixed chat drawer crowds the exercise.
- **Tablet:** lesson content uses the full reading width and the tutor follows as a large reviewable panel.
- **Desktop:** outline, learning content, and tutor form a three-column layout; the activity remains the widest region.

## Recovery and system behavior for implementation

The production design must add these fixture-backed states in Mission 01A:

- initial loading and skeleton with stable reading order;
- no enrolled course and no due review;
- offline with preserved local attempt;
- save pending, saved, and save failed;
- session expired without discarding the current response;
- source unavailable or under editorial review;
- AI source insufficiency and tutor unavailable;
- incorrect, partially correct, correct, and manual-review feedback;
- completion with reduced-motion equivalent;
- content correction notice and revised lesson version.

Every error states what happened, what was preserved, and the next safe action.
